# Roadmap

A row is a promise and the acceptance that proves it. A stage is done when its
story passes, not when its code lands. The acceptance names what is true after
the feature and what was true before it.

| Stage | Delivers | Acceptance | Status |
|-------|----------|------------|--------|
| M0 | Workspace, CI subtree, layers declared | `make lint` green on an empty crate set | done |
| M1 | The queue: tree, state machine, scheduler | A queued task runs, pauses on preempt, resumes its frame, and a parent waits its children — proven by stories that fail without the queue | done |
| M2 | Session log + projection; one provider | A session resumes from its JSONL; a projection keeps the tail and drops nothing from the queue; a mock provider answers offline | done |
| M3 | Tools + per-OS sandbox | An anchored edit reverts to the original bytes; a climbing path is rejected; a confined process writes inside the workspace and is denied outside it, executed for real on macOS, Linux, and Windows | done |
| M4 | The agent loop | A task crosses the wire and persists; steering drains at the boundary into the session; two tasks complete in order | done |
| M5 | The single-focus view | The view renders one flat level with badges and a cursor; narrowing shows a subtree | done |
| M6 | The live queue surface | Run `pearl queue` and the tree is a live single-focus list you edit by keyboard: take a queued node into the hand, edit it, place it back at a new position or as steering; hold/resume/steer/redirect/cancel on the focused line. Before this the surface was render-only and `pearl queue` printed a placeholder | done |
| M7 | Tool-calling loop | The agent calls read/edit/bash through the queue, an edit is revertible from the session, and the compiler feeds diagnostics back — no LSP | done |
| M8 | Subagents under the queue | A node fans out to derived sessions (`spawn`), each subagent runs its own loop (`run_subagent`) and settles as a queue event; the parent finishes only when every child settles, and the human keeps one focus. Before this a node was a single session with no fan-out | done |
| M9 | Distribution | A release tag runs `make release-check` and `make dist` on each of macOS, Linux, and Windows, and attaches one native binary per platform to the release page, so a user downloads and runs PEARL without a Rust toolchain. Before this, a binary existed only where someone had compiled it | done |
| M10 | Revertible shell | A bash op that creates, edits, or deletes files is reverted by op id to the exact prior bytes; each op's baseline is independent; the op's output reaches the model. Before this, bash was confined but its effects were permanent | done |
| M11 | Concurrent fan-out | Subagents run at the same time, each in its own workspace copy (ADR 15), proven by two children meeting a barrier that a sequential fan-out could never open; one child's writes never appear in another's copy or in the parent's tree. Before this, subagents ran one after another on the shared tree | done |
| M12 | Aside | A side question is answered against the session read-only and shown on the surface; the queue gains no node and the log gains no entry. Before this, every question had to become work or wait | done |
| M13 | Compaction that runs | A session that outgrows 75% of its window folds its oldest turns into a summary the model wrote, appends it with the range it covers, and the next request is smaller and still carries the work; a process that reopens the session reuses that summary without asking a model again, and the estimate of the context learns from each completion's billed `prompt_tokens`. Before this, `project` existed and no caller ran it, the summary was a count of entries, and nothing measured the context. Proven by `crates/pearl-agent/tests/compaction-tests.rs` and `crates/pearl-session/tests/compaction-tests.rs` | done |
| M14 | The surface runs what you place | A task placed on the surface is picked up by the scheduler, runs while the list stays editable, and reports its state as a badge: running, paused on preempt, done, failed. Before this the surface edited a queue nothing executed, and `pearl run` was the only way to start work. Proven by `crates/pearl/tests/surface-tests.rs`, `crates/pearl/tests/runner-tests.rs` and `crates/pearl-agent/tests/surface-tests.rs` | done |
| M15 | The report reaches the eye | The focused task's reply is on the screen beside the queue, without entering a mode or opening the log; a failure shows its reason, a long reply shows its newest line, and a task that has not run says so. Before this the surface drew a badge and a title, and the answer existed only in `pearl-session.jsonl`. Proven by `crates/pearl-tui/tests/report-tests.rs` and `crates/pearl/tests/surface-tests.rs` | done |
| M16 | The wait says what it is waiting for | While a task runs, the pane names the act — `asking the model`, or the tool and the file or command it touches — so the seconds of generation are not a blank. Before this a running task said `no report yet` and the badge said only that it was running. Proven by `crates/pearl-core/tests/activity-tests.rs`, `crates/pearl-agent/tests/activity-tests.rs`, `crates/pearl-tui/tests/report-tests.rs` and `crates/pearl/tests/surface-tests.rs` | done |
| M17 | A refused key says why | A key that does not apply to the focused task puts its reason on the screen in the task's own words — the state it is in and the state the move needed — and a refused placement keeps the request in the hand. Before this every refusal was swallowed by `let _ =`, so `resume` and `take` looked like a broken tool. Proven by `crates/pearl-tui/tests/notice-tests.rs` and `crates/pearl/tests/surface-tests.rs` | done |
| M18 | Append means the end | Tasks sent in order appear in that order. Before this `a` placed each new task after the focus, so hello1, hello2, hello3 read as hello1, hello3, hello2 with nothing on screen explaining it; `p` keeps its meaning of placing a taken request after the focus. Proven by `crates/pearl-tui/tests/order-tests.rs` | done |
| M19 | A knob turns while the work runs | `:` sets the model, the thinking effort, and the fold window or fraction; the next request carries them and a status line names what is in force. Before this the model was fixed at launch, effort did not exist, and the window was a constant no one could reach. Proven by `crates/pearl-core/tests/settings-tests.rs`, `crates/pearl-agent/tests/config-tests.rs` and `crates/pearl-tui/tests/config-tests.rs` | done |
| M20 | A write can be taken back from the keyboard | `z` restores the newest shell op's before-image and says which command it undid; the model can do the same with `revert_bash`. Before this the op id was printed in a tool result and nothing could act on it, so the headline promise had no reach. Proven by `crates/pearl-agent/tests/undo-tests.rs` and `crates/pearl-tui/tests/config-tests.rs` | done |
| M21 | The window's fill and its folds are on the screen | The status row reads `ctx 48k/128k, 1 fold` while work runs, from the same handle the runner writes. Before this a fold was silent, which is indistinguishable from a model that forgot. Proven by `crates/pearl-core/tests/gauge-tests.rs` and `crates/pearl-agent/tests/gauge-tests.rs` | done |
| M22 | Fan-out can be asked for | The model calls `subagent` with titles and gets each child's answer back in the same turn; the copies live beside the workspace. Before this the pool and the concurrent runner existed and no tool offered them, and the copy sat inside its own source, so the first real fan-out died with `File name too long`. Proven by `crates/pearl-agent/tests/fanout-tests.rs` | done |
| M23 | The screen goes where the attention is | No vertical rules; the list windows around the cursor and shows its place in the whole; the report scrolls back and resumes following when the cursor moves; `Tab` cycles split/report/queue. Before this the panes were boxed, a queue past its pane lost its tail including the focused task, and a long report could only be read from its end. Proven by `crates/pearl-tui/tests/layout-tests.rs` | done |
| M24 | Thinking is kept and told from the answer | The endpoint's `reasoning_content` is recorded under its own role and shown folded, opened with `T`; it is never sent back and never folded into a summary. Before this the effort knob existed and its entire output was discarded. Proven by `crates/pearl-provider/tests/reasoning-tests.rs` and `crates/pearl-agent/tests/reasoning-tests.rs` | done |
| M25 | A nested part runs before its whole | `n` nests a part under the focused task; the scheduler is depth-first, a held part holds its subtree, a failed part does not strand the whole, and the parent's first request carries each child's finding. Before this `add_child` existed and the scheduler walked only roots, so a nested part was work nobody would ever pick up. Proven by `crates/pearl-core/tests/nesting-tests.rs` | done |
| M26 | The status bar is the control panel | Each reading names its key; `M`/`E`/`W` step model, thinking effort and window; `S` keeps every knob at once in `~/.pearl/config`, in the `:` prompt's own language, loaded at startup. The cache hit rate is shown. Before this the window was stated twice, `fold` was jargon, the cache was not parsed, and no knob survived the process. Proven by `crates/pearl-core/tests/{settings,cache}-tests.rs` and `crates/pearl-tui/tests/config-tests.rs` | done |
| M27 | Three keyboards, one product | `K` cycles plain/vim/emacs; each is authentic (vim's `C-u`/`C-d`/`gg`/`G`, emacs's `C-n`/`C-p`/`M-v`/`C-x o`/`C-g`, plain needs no key a MacBook lacks), the motion row is written from the style, and the choice saves with the other defaults. Actions keep their letters in all three. Proven by `crates/pearl-tui/tests/keys-tests.rs` | done |
| M28 | The key can come from ~/.authinfo and name its house | The house's env var wins, else an authinfo `machine` line for the endpoint's host; the status reads `deepseek/deepseek-chat (M)` and the `M` ladder is the house's own, an unknown house leaving the chosen model alone. Before this only `DEEPSEEK_API_KEY` was read and the model ladder was DeepSeek's regardless of endpoint. Proven by `crates/pearl-provider/tests/auth-tests.rs` | done |
| M29 | The process's footprint is on the screen | `mem 14M` is resident memory read from the OS each frame on all three platforms, with no new dependency. Before this nothing said what the process was holding, and a long session reads its whole log on every request. Proven by `crates/pearl-tools/tests/footprint-tests.rs` | done |
| M30 | Every turn, task and the session are costed | The report itemises each turn (`turn 2  ↑1.2k ↓340 0.4s`), the queue row carries the task's total, the status line the session's; a child is charged to itself and an aside to the session. Before this nothing said what any of it cost or how long it waited. Proven by `crates/pearl-core/tests/cost-tests.rs` | done |
| M31 | The ground is named | A row reads `~/proj  git:main*8  sandbox:workspace-write`: the directory writes land in, the branch and its changed count (untracked included, `*?` when unasked), and the policy actually in force from one declaration. Before this the human had to guess all three. Proven by `crates/pearl-tools/tests/place-tests.rs` | done |
| M32 | A small window loses whole items, not half words | Every row fits whole items and marks the drop with `…`; `? keys` and `q quit` survive any width and `?` opens the full legend; height yields the ground row first and the answer last. Layout is `1`/`2`/`3` with no pane focus, and each motion key names its window. Before this every row was cut mid-word and a 30x7 window lost the answer entirely. Proven by `crates/pearl-tui/tests/layout-tests.rs` | done |
| M33 | Either window scrolls by line or by page | One rule -- plain key = queue, Alt = report, Shift = page -- gives both windows a line and a page motion in every style, on top of vim's and emacs's own chords; a page is the window's height and paging the queue carries the cursor. Before this the report had no line motion at all and the queue had no page motion, and C-d/C-u scrolled the report while looking like vim's window scroll. Proven by `crates/pearl-tui/tests/keys-tests.rs` | done |
| M34 | One header, one footer | The first line leads with the wordmark and carries model, context, the sandbox's directory, git and the bill; the last carries the keys. The sandbox is named as a directory (`write:~/proj`) rather than a policy word, and `n` says what nesting does (`part of "X" (runs before it)`). Before this four furniture rows split the same facts and `workspace-write` never said which directory. Proven by `crates/pearl-tui/tests/keys-tests.rs` | done |
| M35 | A narrowed view says where it is | The heading reads `queue 1-2 of 2 in "fix the parser"` instead of `(narrowed)`. Proven by `crates/pearl-tui/tests/layout-tests.rs` | done |
| M36 | One sandbox policy means one thing on every OS | Reads open on macOS, Linux and Windows; writes are the workspace plus `$TMPDIR` and `/tmp`, so an agent can write a script and run it; the header names the whole boundary as `write:~/proj+tmp`. Before this Windows could read nothing outside the root and no OS could write scratch. Proven by `crates/pearl-tools/tests/sandbox-tests.rs`, which runs a real confined script | done |
| M37 | Each style keeps its own letters | Plain moves with arrows and pages with `PgUp`/`PgDn` (`fn+↑↓` on a MacBook); `j/k` and `J/K` answer only in vim. Layout is one item, `1/2/3 queue/report/both`, and the single key row leads with adding, moving and reading rather than spending itself on actions. Before this vim letters were universal and appeared in the plain legend. Proven by `crates/pearl-tui/tests/keys-tests.rs` | done |
| M38 | The row and help share one grouped order | start / look / work / safety / ask / set, flattened for the row and headed for `?`, with the readings appended; M/E/W are named only beside their readings; an open prompt owns the bottom row; help too tall for the window says how much it hides. Before this help was four unlabelled piles in a different order, and merging the rows had put the legend over the human's typing. Proven by `crates/pearl-tui/tests/layout-tests.rs` | done |
| M39 | The window ladder reaches the windows models actually have | `W` walks 16k, 32k, 64k, 128k, 200k, 256k, 400k, 1M; the fold threshold stays a share of whichever is chosen. Before this the ladder stopped at 128k, so a Claude- or Gemini-sized window could only be typed by hand. Proven by `crates/pearl-core/tests/settings-tests.rs` | done |
| M40 | Every style offers the same eight motions | A line, a page and both ends of each window, plus the level in and out, in plain, vim and emacs alike: `Home`/`End` and `Alt+Home`/`Alt+End` are universal, vim adds `Alt+gg`/`Alt+G`, emacs `C-M-<`/`C-M->` and its `C-M-S-v` page. Before this plain had no ends at all and no style could reach the report's oldest line. Proven by `crates/pearl-tui/tests/keys-tests.rs` | done |
| M41 | The models to choose between are the human's list | A candidate is an endpoint and a model id; the house is derived and the key is not a field. `:` takes `models`, `add`, `edit`, `remove`, `choose`; the list and the choice survive `S` and a restart. Before this the ladder was a two-house table in the code and an unknown house had no ladder at all. Proven by `crates/pearl-core/tests/catalog-tests.rs` | done |
| M42 | A request goes to the endpoint the choice names, with that endpoint's key or none | `Houses` resolves endpoint and credential per request; a keyless local endpoint is asked with no Authorization header and the surface starts without a key. Before this the endpoint and key were fixed at launch, so choosing another house sent its model name to the wrong server, and no key meant no runner. Proven by `crates/pearl-provider/tests/houses-tests.rs`, which answers a real request from a local socket | done |
| M43 | The model key cycles a short list and opens a long one | Three rows or fewer cycle; more open a picker where arrows move, `RET` chooses and `a`/`e`/`d` add, edit and drop, with `e` carrying the row into the prompt. A row with no findable key says so; the header names the chosen candidate's house. Before this `M` always cycled blind and the header named the launch credential's house. Proven by `crates/pearl-tui/tests/picker-tests.rs` | done |
| M44 | The encrypted authinfo is read | A user whose keys live in `~/.authinfo.gpg` gets them: the path falls back to the encrypted form when no plaintext file exists, and a `.gpg` file is decrypted by the user's own gpg (`--batch`, a bounded wait) and parsed like any authinfo. A file that cannot be decrypted is no key, never a fallback to reading ciphertext as text, and when neither form exists no path is offered. Before this the `.gpg` form was not read at all and `default_path` offered a plaintext path that need not exist. Proven by `crates/pearl-provider/tests/auth-tests.rs` | done |
| M45 | Thinking is one ladder of intent, spoken in the house's dialect | `auto/off/minimal/low/medium/high/max` is the intent; the dialect says which rungs a house can express and which fields carry them. DeepSeek has none (its model id decides) and `E` says why it did not move; a rung the dialect cannot express is refused with the ones it can, never downgraded. Before this one word was sent verbatim to every house, so `off` meant `auto` and `high` on DeepSeek was a field silently dropped. Proven by `crates/pearl-core/tests/dialect-tests.rs` | done |
| M46 | A refusal speaks, and a refusal about thinking teaches | A non-2xx answer carries its status and the endpoint's own message; one naming a thinking field drops the dialect to `silent`, says so on the task and retries once. The header names a stated or learned dialect. Before this a 400 became "the response had no usable choice" and the human had to guess which knob to turn. Proven by `crates/pearl-agent/tests/config-tests.rs` and `crates/pearl-tui/tests/config-tests.rs` | done |
| M47 | A one-shot run reads the same knobs as the surface | `pearl run` builds its settings from the kept file and the launch house, and hands them to the agent. Before this it built fresh defaults and never attached them, so every kept choice -- dialect, rung, window, model list -- was ignored and the agent used its own. Proven by `crates/pearl/tests/knobs-tests.rs` | done |

| M50 | Vim pages with bare `f`/`b`, and the aside moves to `/` | The vim motion list reads `j/k/f/b/gg/G` and the report `M-j/M-k/M-f/M-b/M-gg/M-G`; `C-f`/`C-b` are unbound. `/` opens the aside in all three styles, so no letter means two things in one style and nothing in another. | M53 | A row is written in two stages, address then id | `a` and `e` in the model list ask for the address first, offering every distinct endpoint already in use plus the launch endpoint plus a last row to type a new one, then ask for the model id by hand against the address just chosen. | M54 | A refused rung is remembered, marked, and filed per address | A 4xx whose message names a thinking field files the rung in force against the address that answered, returns `effort` to `auto`, and retries once without the field; the `E` list keeps the row and prints why it is not in force; `e` steps over it; another house is unaffected; `S` writes `refused <address> <rung>` and `refused clear` forgets them. Before this the whole dialect dropped to `silent`, so one wrong word took every rung with it, nothing said which word, and the surface could not tell the human why its list had shrunk. Before this one refusal about the field cost four more 400s, the budget could exceed `max_tokens` and blame the model, a copied URL asked for `/chat/completions` twice, and an Anthropic path got a 404 four turns later. Proven by `crates/pearl-provider/tests/wire-tests.rs`, `crates/pearl-core/tests/catalog-tests.rs` and `crates/pearl-tui/tests/picker-tests.rs` | done |
| M56 | One ladder for every house, marked where the house cannot say it | `Effort::ladder()` is the vocabulary -- `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` -- and a dialect says which part of it it can put on the wire. `E` lists the whole ladder and marks each row this dialect cannot say (`xhigh`, invented by one house, is a strength the number houses can be asked for). ## Deliberately leaves out

- **LSP** (ADR 4): the compiler is the feedback channel; no language server the
  user must install.
- **An editor view**: the agent generates the code; the human shapes the queue.
- **Parallel attention**: subagents are many hands under one queue, but the
  human tends one focus.
- **A container**: the boundary is a copy, a confinement you can see and kill.

## Before a tag

Re-read the four pages and the records top to bottom; the tag is the one moment
where a stale sentence is published. Run `make release-check` and `make dist` on
each platform.

## How to use this page

Move a row to `done` only when its story proves it, in the commit that makes the
story pass. If an acceptance itself was wrong, edit this page first, as the
process in `AGENTS.md` requires.
| M57 | A row is offered the addresses it can actually reach, and a remark dies with its act | `a` and `e` offer the bases the major houses publish after the launch endpoint, each address once, so a human pointing a row at OpenAI is not left to remember a URL; a notice is the answer to one act and the next key ends it, so `model id for the launch endpoint` cannot outlive the stage it described. Before this the list held only what the config already named, and a remark set by an abandoned stage stayed on screen until Esc happened to clear it. Proven by `crates/pearl-tui/tests/picker-tests.rs` and `crates/pearl-core/tests/catalog-tests.rs` | done |
| M61 | A replayed session is the conversation it recorded, tool calls and all | A request built from the log carries the assistant turn's tool calls and each tool turn's `tool_call_id`, because the wire refuses a tool turn that answers nothing -- DeepSeek said `messages[84]: missing field tool_call_id` on a task whose replay held the previous task's calls. A turn written before ids were recorded is left out of the replay instead of being sent bare. Before this every tool result went out without the id it answered, so a session that had used a tool could not be resumed. Proven by `crates/pearl-agent/tests/replay-tests.rs` | done |
| M60 | The published addresses are the ones the houses document, and the launch endpoint is offered once | Each base on the list answers a keyless request (401/403/429) and is named in that house's own documentation; the list covers the houses a person is likely to pay -- OpenAI, Anthropic, DeepSeek, Gemini, xAI, Groq, Mistral, DashScope, bigmodel, Moonshot, MiniMax, MiMo, Volcengine Ark, Qianfan, Hunyuan, TokenHub and Spark -- and the aggregators that reach several of them through one key: OpenRouter, SiliconFlow and Ofox. | M62 | A row that is cut can be read again, and a prompt shows its end | A task title too long for its row is shortened with a mark and the rest of the request is one keystroke away (`v`), wrapped on a screen with the same motion as the other windows; the bill and the child count keep their columns and the title yields to them; the prompt keeps its label, shows the tail of what is being typed rather than the head, and is drawn in the ordinary foreground instead of the legend's grey. | M63 | A command may write to the null device under every policy | `2>/dev/null` is the commonest redirect in a shell command and it writes to nothing, so a sandbox that refuses `/dev/null` fails work that could not have changed anything -- a live task asked for `ls -la 2>/dev/null \|\| dir`, was refused with `sh: /dev/null: Operation not permitted`, fell through to a command that does not exist and cost three model turns for a one-turn answer.
